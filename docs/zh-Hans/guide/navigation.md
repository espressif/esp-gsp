# 导航、视口与手势

## 场景导航

| 需求 | 组件 |
|---|---|
| Bundle 内场景切换 | Scene navigation |
| 同一场景中的连续页面 | PageFlow / TabView |
| 入栈、返回式导航 | StackView |
| 从边缘显示面板 | Drawer |
| 大数据纵向浏览 | List / Wheel / Message List |
| 多列数据浏览 | Grid |

场景坐标是逻辑坐标。父节点位置、裁剪和导航变换会影响子节点；应用不应通过手工叠加
另一个对象来模拟组件内部页面或滚动偏移。

同一 Bundle 的场景通过 `gsp_add_bundle(SCENES ...)` 按顺序加入。可用 JSON `goto`
动作或 `esp_gsp_goto_scene()` 切换；横向场景滑动默认启用，可通过场景 `"swipe":
false` 或 `esp_gsp_set_swipe_enabled()` 禁用。

## 视口组件

PageFlow、TabView、StackView、Drawer、List 和 Wheel 在同一场景的有界视口内移动并
裁剪子内容，只使受影响视口失效。它们适合局部页面、堆栈、抽屉或滚动集合，不应用
场景切换模拟内部滚动，也不应把大量应用数据展开为静态对象。

PageFlow/StackView 动画会冻结源页和目标页；跨越多个逻辑页也不会露出中间页。视口
Buffer 分配失败时页面仍原子完成切换，低内存目标不会因为动画失败而丢失最终状态。

## 手势优先级

点击、拖动、滚动、组件滑动和场景滑动共享同一输入路径。运行时根据起始区域、方向、
阈值和当前组件决定手势归属。不要在应用层重复实现同一指针状态机。

- 可滚动集合优先处理其滚动方向；
- Drawer 由边缘区域和方向触发；
- PageFlow/StackView 处理其页面方向；
- 未被内部组件消费的横向拖动才可能成为场景滑动。

距离阈值、速度窗口和回弹时间属于固件级 Kconfig 策略。可先使用默认值，再根据目标屏幕
和触控手感调整。

## 动画与回退

转场可以使用快照、移动、淡入淡出或组件自身的保留态动画。内存或目标能力不足时，
运行时必须走已定义的低资源回退，而不是丢失最终页面状态。主机预览可以验证交互语义；
在目标板上检查撕裂、帧率和触控手感。

## 跨页面动画

Scene、PageFlow 和 StackView 的动画目标都是确定的源与目标。应用只提交目标场景或
页码，不在业务代码中逐帧修改位置。Cross-fade 需要两份 Scene Snapshot；内存不足时
使用定义好的 Fade-through-black 回退。重复快照失败会降低重试频率，一次成功捕获后
恢复正常节奏。

## 运行时定位

需要移动命名控件时使用生成的位置操作或公共组件属性 API。坐标仍相对于父对象，受父
节点裁剪和布局约束。对于 Row/Column 布局，让布局字段决定主轴位置；不要同时用应用
Setter 与布局系统争夺同一坐标。

函数签名见[函数级 API 参考](../reference/api-functions.md)。
