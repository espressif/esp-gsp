# 介绍

ESP-GSP 是面向 ESP-IDF 的预编译 UI 工具链与有界图形运行时，适用于需要可评审界面源码、确定性资源、稳定应用接口，并由 BSP 掌控显示链路的产品。

## 提供的能力

| 能力 | 职责 |
|---|---|
| 声明式场景 | JSON 负责层级、布局、样式、静态资源和局部动作。 |
| 编译式 Bundle | GSPC 校验输入，将场景与资源打包为带版本的 GSPB 数据。 |
| 类型化集成 | 稳定名称产生 setter、getter、事件判断和组件适配接口。 |
| 可移植渲染 | 同一核心通过 WebAssembly 在本地预览，通过 ESP-LCD 在设备渲染。 |

## 职责边界

| 内容 | 负责层 |
|---|---|
| 结构、外观、静态资源 | 场景 JSON |
| 校验、资源转换、Bundle/API 生成 | GSPC |
| 产品状态、网络、存储、传感器 | 应用任务 |
| 屏幕时序、旋转、缓冲区、触控映射 | BSP 与 ESP-LCD 显示目标 |
| 渲染、输入分发、组件状态 | ESP-GSP 运行时 |

运行时不替代 BSP，JSON 也不隐藏产品逻辑。UI 回调应向应用任务发出请求；应用完成状态变更后，再通过生成 setter 更新界面。

相机、视频或持续产生的像素使用 Canvas；偶尔替换的编码图片使用运行时图片 API；大型应用数据集使用 List、Grid、Wheel 或 Message List，而不是为每条数据创建一个静态对象。

继续阅读[安装与集成](../getting-started.md)，或浏览完整[控件库](../components/index.md)。

## 何时选择其他路径

- 相机、视频或其他持续产生像素的生产者使用 Canvas。
- 偶尔替换 PNG、JPEG 等编码图片时使用运行时图片 API。
- 大型应用集合使用 List、Grid、Wheel 或 Message List，通过可见项复用控制内存。
- 产品网络、存储、认证、更新和业务状态继续放在应用层；不要把它们迁入场景或渲染回调。

这些能力可以组合使用，但仍共享同一条生成、运行时和显示集成路径，不形成第二套框架。
