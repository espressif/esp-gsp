## 数据概览

**读表方式：** 数值对均为 GSP / LVGL。“差异”列表示 GSP 相对 LVGL：帧率高出 5% 以上时给出帧率倍率，否则给出 CPU 相对变化。CPU 按全部核心平均，双核约 50% 即一个核满载。非动图更新按 60 Hz 请求，S3 本显示配置的轻载帧率约为 42 FPS。以下汇总仅覆盖本组已测配置。

- **固定装饰更省 CPU：** 32 层固定半透明卡片帧率相近，CPU 降低 75%（S3）/ 85%（P4）。
- **图片滚动更流畅：** P4 上 16 / 64 张 PNG 裁图滚动均约 58 FPS，LVGL 为 30 / 4.4 FPS。
- **列表与动图：** S3 的 1024 行列表帧率为 1.39×，4 视图 Cube 为 2.45×；P4 单张 Cube 帧率相近，CPU 降低 79%。

<summary>概览如何计算</summary>

- **可比结果：** 全部主配置的帧率场景，不含静态停留、交互回放、帧准备吞吐与 PPA 参考配置。帧率比在 0.95～1.05 之间按帧率相近归类。

</details>

## GSP 的优势从哪里来

GSP 把能在构建期确定的工作提前完成，减少运行时计算：

- **固定内容预渲染（烘焙）：** 背景、刻度、卡片等固定装饰在构建期合成为图像，运行时复用，并与实时数值和标记合成。
- **图片预转换：** PNG 在构建期转换为运行时资源，避免设备端解码原始 PNG；压缩资源仍需解码。
- **动图预处理：** GIF 在构建期转换为动画资源并预处理帧间差异，减少设备端的帧准备与重绘开销。

本组 LVGL 使用原生对象和 PNG / GIF 播放路径，其界面可在运行时灵活构建和修改。固定内容越多、素材越确定，越能发挥 GSP 预处理的作用；预处理可能增加 Flash，见[内存与 Flash](#内存与-flash)。

## 适用范围

本组 GSP 的优势集中在固定装饰、预置素材和密集更新。轻载场景双方接近，单矩形换色和移动卡片的 GSP CPU 分别略高 7% 和 3%。结果包含 GSP 构建期预处理的收益；LVGL 可选的预转换素材、图片序列和其他解码器未纳入，不代表其专项调优后的上限。

<details>
<summary>统计口径</summary>

- **FPS：** 每秒成功提交的画面数，不是屏幕光学刷新率；单动图和混合界面的计数范围见对应小节。
- **CPU：** 差异列为相对变化，按未舍入值计算，不是占用率的百分点差。
- **重复测量：** 预热后独立启动两次，先按单次启动汇总，再取中位数。CSV 中的观测范围不是置信区间；±5% 仅用于帧率归类，不代表统计等效。
- **资源：** 统计完整应用；静态 SRAM 来自 ELF，最低余量为各次启动的最低可用 heap 再取中位数。PSRAM 含代码驻留与动态分配，不与 ELF 载荷直接相加。KiB / MiB 分别为 1,024 / 1,048,576 字节。

</details>
